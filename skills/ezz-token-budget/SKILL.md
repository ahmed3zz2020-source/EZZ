# ميزانية التوكنز — مؤسسة EZZ + office

## القاعدة الحاكمة (مُقاسة)

**تكلفة التشغيل الواحد ≈ 5,450 توكن** (وكيل مخصص + سياق نظيف).
**التكلفة = عدد التشغيلات × 5,450.**

⛔ **السبب الحقيقي لتسرّب الكريديت مش عدد التشغيلات — كان السياق المتراكم.**
جلسة ثابتة بتخزّن ~640-770 توكن **كل تشغيل** ⇒ بعد أسبوعين السياق ≈ 138k ⇒ كل تشغيل بيعيد حقن كل ده بسعر كامل.

| | توكن/تشغيل | مصدر القياس |
|---|---|---|
| جلسة نظيفة (وكيل مخصص · `mode:new`) | **5,450** | `session_messages` → `usage.total_tokens` |
| جلسة ثابتة متراكمة | **138,277** | جلسة `gold-engine-keepalive` |
| **الفرق** | **٢٥ ضعف** | |

## الإجراء (استخدمه قبل أي كرون جديد وبعد أي تعديل)

### ١ — امسح التكرار
```bash
# كل الكرونات النشطة مع جدولها وجلسة كل واحد
```
⛔ **ممنوع كرونين بنفس الوظيفة على نفس المورد.** العَرَض: fighting على getUpdates (409) أو نفس السكربت بيشتغل مرتين، مع حرق كريدت بلا دالة.
كل كرون نشط لـ«نفس البوت / نفس السكربت / نفس الـKV» ⇒ واحد بس.

### ٢ — كل كرون متكرر = `mode:new`
في `cron_create` / `cron_update`:
```json
{"session": {"mode": "new"}}
```
⛔ `mode:sessionId` أو `mode:fixed` ⇒ الجلسة بتتراكم. لو لازم جلسة ثابتة ⇒ UUID مثبّت + تدوير كل ~٣٠ يوم (سقف 512k).

### ٣ — التزم بالحدود
- ⛔ **ممنوع كرون أسرع من ١٥ دقيقة** على أي مسار LLM (كل ٥ دقائق = 288 تشغيل = ~1.57 مليون/يوم).
- ⛔ **مهمة واحدة لكل وكيل** — كرون بيشغّل أكتر من مهمة = كرون بيلدفع مرتين.
- ⛔ **قبل أي كرون جديد: هل ممكن تتعمل بـbash أو Worker؟** الـWorkers (`ezz-gate` · `ezz-gate-send`) = **صفر توكن**. مهمة قراءة-كتابة بلا تفسير ⇒ Worker.

### ٤ — سجّل
كل كرون جديد ⇒ سطر في `ops/TOKEN-BUDGET.md` (التكرار + عدد التشغيلات/يوم + التكلفة + مصدر القياس).

### ٥ — قِس بعد التشغيل
```bash
# session_messages على UUID الجلسة ⇒ usage.input_tokens + usage.cache_read
```
⚠️ `session_messages` **بيرفض الـsession_id الرقمي** ⇒ خُد الـUUID من `cron_read view=runs` أو `session_list`.

## ⛔ عند `42212 Token Plan usage limit reached`

١. أوقف فوراً آخر كرون اتضاف.
٢. راجع `ops/TOKEN-BUDGET.md` + سجل اليوم (مين ate الكريديت).
٣. اتأكد: مفيش كرون مكرر · كل المتكرر `mode:new` · مفيش مسار أسرع من ١٥ دقيقة.
٤. متكمّلش أي كرون جديد لحد ما السبب يتقفل.

## المعايرة الفعلية (١ نوفمبر ٢٠٢٦)

حذف `gold-engine-keepalive` (*/7 = 205 تشغيل/يوم) · تعطيل `بوابة الاستقبال` (*/5 = 288 تشغيل/يوم) · إعادة بناء ٨ كرونات بـ`mode:new` · حذف ٥ كرونات مكرّرة · تذكير RapidAPI من يومي لأسبوعي · وكيل «موازن-التوكنز» + مراجعة أسبوعية.

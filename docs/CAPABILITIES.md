| ⛔ **CI على GitHub Actions** | التوكن بلا scope `workflow` | `ezz-mem.py doctor` كـgate محلي + فحص قبل push |

## ٦) القيود التشغيلية المؤثرة على التصميم

| القيد | الأثر | قرار التصميم |
|---|---|---|
| cron session = حاوية منفصلة | عملية طويلة تت restarting ⇒ عمرها ما بتكمّل | العمليات الطويلة = حاوية دايمة؛ الكرون = مراقبة/إبلاغ |
| كل cron = session = reinjection كامل | 24,400 توكن لكل تشغيل | ⛔ لا كرون متكرر بلا سطر تكلفة · وكيل صغير للكرونات |
| KV سقف 1000 write/يوم على مستوى الـaccount | الكتابة كل نبضة = استهلاك | ⛔ اكتب عند التغيّر فقط |
| GitHub raw كاش ٥ دقايق | قراءة قديمة = قرار غلط | ⛔ اقرأ من contents API بـ`Accept: application/vnd.github.raw` |
| ذاكرة كل agent معزولة | ما ينفعش تنسيق بالذاكرة | ⛔ التنسيق = المستودع + KV |
| sandbox بيتصفّر بين الشاتات | الشغل الميت يضيع | ⛔ كل أثر حي = GitHub أو KV أو Drive |
